# Species Audit: Halfling

## Summary

No `race`-type item exists for Halfling in the compendium (`raceItemExists: false`), and every one of the 8 trait `feat` items has completely empty `effects`/`activities`/`advancement`, matching the pack-wide findings. Re-running the current pipeline (working tree HEAD, see note below) against this species' actual prose would still leave **7 of 8 traits mechanically empty** — not because the code is stale, but because no detector in `scripts/scraper.mjs` targets these particular rule shapes (reroll-on-1, conditional Hide, advantage-vs-condition, movement-through-space). The one trait that plausibly *should* produce an advancement entry — **Ability Score Increases** — is also a miss, but for a different reason: `guessAbilityScoreImprovement` only recognizes the flat-feat/Epic-Boon ASI phrasing ("increase one ability score of your choice by 2, or increase two ability scores of your choice by 1"), not the species-level phrasing actually used here ("increase one score by 2 and a different one by 1, **or increase three scores by 1**"). This is a real, previously-undocumented gap — confirmed empirically below, not in any of issues 001–019 — and because the species ASI boilerplate is standardized across all nine 2024 PHB species, it likely affects every one of them, not just Halfling. Separately, **Size** and **Speed** are correctly *not* supposed to be built as trait-level mechanics at all (they belong on the race item's own `Size`/`movement` data) — but since no race item exists for Halfling, that data doesn't exist anywhere either.

**Note on "current code":** the working tree has uncommitted edits to `scripts/scraper.mjs`, `scripts/effects-builder.mjs`, and `scripts/importer.mjs` that already implement issues 016 (DC formula/uses-recovery), 017 (activation/range/target/toggle-linking), and 019 (always-prepared spell detection widening) — despite the task brief describing 016–019 as still-open proposals, `git diff` shows this code, not just the issue write-ups and tests, already sitting on disk unmerged. This audit evaluates against that on-disk code (what would actually execute on a re-import right now). It makes no difference to Halfling specifically: none of its 8 traits contain a DC clause, dice/damage/healing language, a spell grant, or a reaction/bonus-action-gated toggle, so every one of these uncommitted detectors is a no-op here.

## Traits

### Ability Score Increases
- **Prose:** "When determining your character's ability scores, increase one score by 2 and a different one by 1, or increase three scores by 1. None of these increases can raise a score above 20."
- **Expected (current code):** `guessAbilityScoreImprovement` (`scripts/scraper.mjs:881-910`) only matches a sentence containing `Increase (your|one ability score of your choice|two ability scores of your choice)` (regex at line 884). Verified directly against this exact string with `guessAbilityScoreAdvancement()` — it returns `null`. The species phrasing never says "one ability score of your choice" or "two ability scores of your choice"; it says "one score by 2 and a different one by 1... or increase three scores by 1" (a 2024-species-specific +2/+1-or-+1/+1/+1 shape, distinct from the flat-feat/Epic-Boon +2-or-+1/+1 shape the function's comment documents as its intended target). No `AbilityScoreImprovement` advancement is built. `guessProficiencyAdvancement` and `scanSegmentText` also find nothing (no proficiency/language clause, no dice/save/effect keywords) — the only thing `scanSegmentText` extracts is a spurious `activation.condition` of "When determining your character's ability scores" (from `TRIGGER_CLAUSE_RE`, `scraper.mjs:320`), but this is never consumed since `guessQueueEntries` (`effects-builder.mjs`) only builds an activity around a save/damage/heal/spell/toggle hint, none of which are present.
- **Actual (compendium data):** `advancement: {}`, `effects: []`, `activities: {}` — matches.
- **Gap / verdict:** Confirmed miss, and confirmed **not** explained by staleness — the current code, run right now, would still produce nothing. This is a new gap not covered by issues 001–019 (issue 009 only wired the *already-correct* ASI regex into `buildAutoMechanics`; it never addressed phrasing coverage). Since the 2024 PHB standardizes this exact "one score by 2 and a different one by 1, or ... by 1" wording across all nine core species, this almost certainly reproduces identically for Human, Elf, Dwarf, Gnome, Dragonborn, Orc, Tiefling, and Goliath.

### Size
- **Prose:** "Your Size is Small (about 2–3 feet tall)."
- **Expected (current code):** No detector in `scanSegmentText` matches this phrasing (it isn't a speed/sense/AC/resistance/dice pattern), so this trait item itself would get no effect/activity/advancement — correctly so, by design: Size is deliberately handled at the **race item** level via `buildSizeAdvancement` (`scripts/ddb-scraper.mjs:248-265`), which maps `raceDef.sizeId` (3 for Halfling, confirmed in issue 014) to a `Size`-type advancement (`sizes: ["sm"]`) on the race item, not by scraping this trait's prose at all.
- **Actual (compendium data):** Empty — matches expectation for the trait item itself.
- **Gap / verdict:** Not a gap in the trait item. But because Halfling has **no race item** (finding #1), the `Size` advancement that `buildSizeAdvancement` would correctly generate (sizeId 3 → Small, per issue 014's own acceptance criteria naming Halfling explicitly) doesn't exist anywhere in this species' data. The mechanism is right; it's just never reached.

### Speed
- **Prose:** "Your Speed is 30 feet."
- **Expected (current code):** Doesn't match any of `scanSegmentText`'s three speed regexes (`scraper.mjs:712-740`, all requiring "walking/climbing/... speed increases by/to N feet" or "you have a ... speed of N feet") — "Your Speed is 30 feet" is a bare, non-directional absolute statement none of those patterns anchor on. Also doesn't match `mergeTraitDerivedMovement`'s `ABSOLUTE_SPEED_GRANT`/`WALKING_SPEED_INCREASES_TO` regexes (`ddb-scraper.mjs:273-274`), which need the same "you have a/an X speed of" or "your base walking speed increases to" wording. No effect built from this trait's prose either way. This is intentional: the race item's base `movement.walk` is meant to come from `raceDef.weightSpeeds.normal` (structured DDB data), not from parsing this descriptive trait.
- **Actual (compendium data):** Empty — matches expectation.
- **Gap / verdict:** Not a gap in the trait item's own handling. Same downstream problem as Size: since no race item exists, the `movement` data this trait describes isn't recorded anywhere in the pack for Halfling right now.

### Luck
- **Prose:** "When you roll a 1 on the d20 of a D20 Test, you can reroll the die, and you must use the new roll."
- **Expected (current code):** No detector anywhere in `scripts/scraper.mjs` or `scripts/effects-builder.mjs` recognizes a reroll mechanic — confirmed by `grep -i "reroll"` across both files returning nothing. `scanSegmentText` only extracts a stray `activation.condition` ("When you roll a 1 on the d20 of a D20 Test") via the same leading-clause `TRIGGER_CLAUSE_RE`, again unused since there's no save/damage/heal/spell/toggle hint to attach it to.
- **Actual (compendium data):** Empty — matches.
- **Gap / verdict:** Confirmed total miss, exactly as anticipated. There is no reroll/"use the new roll" detector, no reroll-related ActiveEffect key, and no issue (001–019) proposes one. Worth flagging as a new gap: Halfling Luck (and its Lucky-feat cousin) is one of the most iconic 5e mechanics and has zero representation in this pipeline's vocabulary.

### Naturally Stealthy
- **Prose:** "You can take the Hide action even when you are obscured only by a creature that is at least one size larger than you."
- **Expected (current code):** Not a proficiency grant (`guessProficiencyAdvancement`'s clause regex requires "proficiency with/in" or "gains training with" — `scraper.mjs:957`), not a dice/save/AC/resistance/sense/speed pattern. Nothing in `scanSegmentText` targets "Hide action" or "obscured." No mechanic generated.
- **Actual (compendium data):** Empty — matches.
- **Gap / verdict:** Confirmed total miss. This is a conditional-action-economy rule (when the Hide action is usable), not a flat Stealth proficiency grant — no existing or proposed detector (001–019) covers it. New gap.

### Brave
- **Prose:** "You have Advantage on saving throws you make to avoid or end the Frightened condition."
- **Expected (current code):** Checked carefully against both candidate detectors: (1) the saving-throw detector (`scraper.mjs:460-469`) requires a **named ability** immediately before "saving throw" (`/\b(Strength|Dexterity|...)\s+saving throw\b/i`) — Brave's text has no named ability, so `savingThrow` stays `null`; (2) the condition-immunity detector (`scraper.mjs:592-640`) requires the literal word "immune"/"immunity" somewhere in the text — Brave never says immune, it grants *advantage*, a mechanically distinct effect. There is no "advantage on saves against condition X" detector anywhere in the codebase (confirmed via `grep -i advantage` across `scraper.mjs`/`effects-builder.mjs`/`ddb-scraper.mjs`, which returns only an unrelated comment). No effect/activity is built.
- **Actual (compendium data):** Empty — matches.
- **Gap / verdict:** Confirmed total miss, and confirmed as a genuinely distinct gap from the immunity detector, as anticipated. A real dnd5e Active Effect key exists for this shape (`system.bonuses.save` style, or an advantage flag scoped by condition), but nothing in the current heuristics attempts it. New gap not covered by 001–019.

### Halfling Nimbleness
- **Prose:** "You can move through the space of any creature that is a size larger than you, but you can't stop in the same space."
- **Expected (current code):** No speed, sense, AC, resistance, or dice keyword present; not a proficiency grant. `scanSegmentText` finds nothing to hint at. There's no dnd5e schema-level flag this codebase's builders target for "move through larger creatures' spaces" (unlike, say, `flags.dnd5e.powerfulBuild` for the confirmed literal "counts as one size larger... carrying capacity" phrasing at `scraper.mjs:572-576` — Nimbleness's phrasing doesn't match that pattern and describes an unrelated movement rule anyway).
- **Actual (compendium data):** Empty — matches.
- **Gap / verdict:** Confirmed total miss. A movement/mobility house-rule with no analogous flag in dnd5e's own Active Effect schema that this pipeline knows to target; no issue proposes coverage. New gap, though arguably lower priority since it's a manual-adjudication rule with no clean single-field representation even if someone wrote a detector for it.

### Creature Type
- **Prose:** "You are Humanoid."
- **Expected (current code):** No detector for creature-type statements exists in `scanSegmentText`. This is consistent with the fact that creature type is handled at the **race item** level: `assembleRaceItem` (`scripts/ddb-scraper.mjs:342-346`) hardcodes `system.type.value: "humanoid"` unconditionally for every imported species, by deliberate design (not derived from trait prose or DDB's `creatureTypeId`, per the comment there) — so this trait's own text is redundant with, not a source for, the race item's actual type field.
- **Actual (compendium data):** Empty — matches expectation for the trait item.
- **Gap / verdict:** Not a gap in trait-item handling; correct-by-design. As with Size/Speed, the actual mechanical value (race item's `type.value`) doesn't exist yet for Halfling because no race item was created.

## Species-level notes

- **Race item absence (finding #1):** `importDdbRace` (`scripts/importer.mjs:929-963`) unconditionally builds all 8 trait items first, then calls `createItemFromData(assembleRaceItem(...), ...)` for the race item itself, wrapped in one outer `try`. Static reading of `assembleRaceItem`, `buildSizeAdvancement`, `mergeTraitDerivedMovement`, and `createItemFromData`/`resolveItemUuids` turned up no explicit species-name-based branch, dedupe-by-identifier check, or "skip if official item already exists" logic that would deliberately exclude Halfling (or the other 8 core PHB species) while allowing Genasi/Warforged/Changeling/Aasimar through — those two groups go through the exact same code path. That points toward the race item's `Item.create(data)` (or something in `resolveItemUuids`) throwing at runtime specifically for these 9 species during that import run, which the outer `catch` in `importDdbRace` would silently route to `report.failed` — but that report isn't part of the data available here, so the precise trigger (e.g. a validation error tied to something distinctive about the 9 core species' DDB definitions) couldn't be confirmed from static code alone. Worth checking the original import's console/report output for the actual `report.failed` entry and error message for one of these 9 species.
- **Folder placement:** All 8 traits sit under `Species/Traits/Halfling` per `raceTraitFolderSegments` (`ddb-scraper.mjs:174-176`) — matches the pack structure described in the brief.
- **Uncommitted working-tree code (016/017/018/019):** as noted in the Summary, these are already implemented on disk, not merged to git, but irrelevant to every Halfling trait's outcome — none contain a DC clause, dice, a spell grant, or a reaction/bonus-action trigger.
- **Most significant finding:** the Ability Score Increases phrasing gap is the one result here that isn't "no detector exists for this kind of rule" but rather "a detector exists, is wired in, and is simply looking for the wrong wording" — and because it's boilerplate shared by all nine 2024 core species, it's likely the single highest-leverage fix available from this audit (one regex change plausibly restores ASI advancement for 9 species at once), separate from the race-item-creation bug.
