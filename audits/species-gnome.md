# Species Audit: Gnome

## Summary

No `race`-type item exists for Gnome (`raceItemExists: false`), and all 8 trait `feat` items have completely empty `effects`/`activities`/`advancement`, matching the pack-wide findings. Re-running the current pipeline (working-tree HEAD — see note below) against Gnome's actual prose would still leave **7 of 8 traits mechanically empty**, for a mix of by-design reasons (Size/Speed/Creature Type belong on the race item, not the trait) and genuine detector gaps. The standout confirmed gaps are: **Ability Score Increases** (species-level ASI phrasing isn't recognized — same root cause already flagged in the Halfling/Human/Dwarf audits, so this is now confirmed across at least four of the nine core species and is almost certainly universal), **Gnomish Cunning** (no "advantage on saving throws" detector exists anywhere in the codebase), and **Gnomish Lineage**, where empirical testing surfaced a previously-undocumented bug: the textual spell/cantrip-name fallback scanner overshoots past a cantrip's name into the following words whenever the sentence says "cantrip" rather than "spell," silently dropping Minor Illusion, Mending, and Prestidigitation. Darkvision is the one trait that fires correctly.

**Note on "current code":** the working tree has uncommitted edits to `scripts/scraper.mjs`, `scripts/effects-builder.mjs`, and `scripts/importer.mjs` that already implement issues 016 (DC formula/uses-recovery), 017 (activation/range/target/toggle-linking), and 019 (always-prepared spell detection widening) — `git diff`/`git status` show this code sitting on disk unmerged, alongside the issue write-ups and new tests. This audit evaluates against that on-disk code (what would actually execute on a re-import right now), and where relevant confirms behavior empirically by calling the exported pure functions (`scanSegmentText`, `guessAbilityScoreAdvancement`, `guessProficiencyAdvancement`) directly under plain Node rather than reasoning from the regex alone.

## Traits

### Size
- **Prose:** "You are Small (about 3–4 feet tall)."
- **Expected (current code):** No detector in `scanSegmentText` (`scripts/scraper.mjs:393-800`) matches this phrasing — it isn't a speed/sense/AC/resistance/dice pattern. Empirically confirmed: `scanSegmentText("You are Small (about 3–4 feet tall).", [], index)` returns every field empty/null. This is correct by design: Size is meant to be handled at the **race item** level via `buildSizeAdvancement` (`scripts/ddb-scraper.mjs:248-265`), which maps `raceDef.sizeId` (3 = Small for Gnome, per the `SIZE_ID_TO_DND5E` table at line 239) to a `Size`-type advancement on the race item, not by scraping this trait's own prose.
- **Actual (compendium data):** Empty — matches expectation for the trait item itself.
- **Gap / verdict:** Not a gap in trait-item handling. But since Gnome has no race item (finding #1), the `Size` advancement `buildSizeAdvancement` would correctly generate never gets attached anywhere — the mechanism is right, it's just unreachable for this species right now.

### Gnomish Lineage
- **Prose:** Intro: "You are part of a lineage that grants you supernatural abilities. Choose one of the following options; whichever one you choose, Intelligence, Wisdom, or Charisma is your spellcasting ability... (choose the ability when you select the lineage):" — then two bolded sub-options: **Forest Gnome** ("You know the Minor Illusion cantrip. You also always have the Speak with Animals spell prepared. You can cast it without a spell slot a number of times equal to your Proficiency Bonus... you regain all expended uses when you finish a Long Rest...") and **Rock Gnome** ("You know the Mending and Prestidigitation cantrips. In addition, you can spend 10 minutes casting Prestidigitation to create a Tiny clockwork device... activate it with a touch [as] a Bonus Action...").
- **Expected (current code):** `guessFeatureMechanics` (`scraper.mjs:833-865`) splits this description into 3 segments via `leadingBoldLabel` (`scraper.mjs:193-206`), since both "Forest Gnome." and "Rock Gnome." open their `<p>` with a `<strong>` tag — confirmed structurally sound, matching the same convention the Elf/Tiefling lineage traits use. Each segment was tested directly against `scanSegmentText`:
  - **Intro segment:** nothing detected (no dice/save/effect keyword).
  - **Forest Gnome segment:** the spell-name fallback (`castRe`, `scraper.mjs:422-429`, widened by issue 019 to also match "have/has/know/knows") correctly finds **"Speak with Animals"** ("you also always have the Speak with Animals spell prepared" — the word "spell" terminates the capture group exactly as intended) and would build a `cast` activity for it via `guessQueueEntries` (`effects-builder.mjs:876-893`). But **"Minor Illusion" is silently missed** ("You know the Minor Illusion cantrip") — confirmed empirically. `castRe`'s repeated-word group only excludes the literal word "spell" from its capture; "cantrip" isn't excluded, so the greedy `{1,4}` repetition consumes "Minor Illusion cantrip You" (4 words) as one candidate, which then fails the `index.has(normalizeName(candidate))` exact-match gate and is silently dropped — never even surfacing as a `spellNames` candidate. This is a genuine, previously-undocumented gap in the fallback scanner, distinct from issue 019 (which only widened the verb list, not the stop-word list). Separately, the recharge clause "a number of times equal to your Proficiency Bonus" is **not** captured by `usesFormula` (`scraper.mjs:438-457`) — that block only resolves a literal `<Ability> modifier` phrase or a literal number word ("three times"/"once"/"twice"); it has no branch for "Proficiency Bonus" as a bare uses-count (unlike `profRe` at line 533, which only feeds *dice/heal/damage* hints, not `usesFormula`). So even if Minor Illusion's overshoot bug were fixed, the resulting Speak with Animals `cast` activity would still get `uses.max: ""` instead of `"@prof"`.
  - **Rock Gnome segment:** **both** "Mending" and "Prestidigitation" are missed for the same cantrip-overshoot reason ("You know the Mending and Prestidigitation cantrips" never terminates before the 4-word cap), and the later "casting Prestidigitation to create a Tiny clockwork device" mention also overshoots ("Prestidigitation to create a", 4 words, no "spell" to anchor on). `parseActivation` (`scraper.mjs:322-337`) does correctly detect `activation.type: "bonus"` from "takes a Bonus Action to activate it," but with no spell/dice/save/status hint surviving in this segment, `guessQueueEntries` never builds anything to attach that activation to — the segment produces **nothing**, not even a placeholder (`preserveUnmatchedLabels: false` when called via `buildAutoMechanics`, `effects-builder.mjs:994`).
- **Actual (compendium data):** Empty — matches (both the stale-import explanation and, per the above, the current code's own actual behavior).
- **Gap / verdict:** Confirmed gap, and a new one: the cantrip-vs-spell stop-word asymmetry in `castRe` is not mentioned in any of issues 001-019, yet it defeats every 2024-era "you know the X cantrip"/"you know the X and Y cantrips" phrasing — a very common shape across lineage/subrace traits (Gnome, likely also Tiefling's Fiendish Legacy and others). The missing `@prof`-based `usesFormula` resolution is a related but separate gap in the same family as issue 016's uses/recovery work, just not covered by it.

### Gnomish Lineage Spells
- **Prose:** "Whichever Gnomish Lineage you choose, Intelligence, Wisdom, or Charisma is your spellcasting ability for the spells you cast with that trait."
- **Expected (current code):** Empirically confirmed nothing fires — no dice, save, resistance, sense, speed, or proficiency clause. This is arguably correct-by-design rather than a gap: the trait describes a **player choice** (which of three abilities becomes the spellcasting ability), and there's no per-item roll-data key or advancement type in dnd5e for "the ability the player picked when selecting a lineage" — the same category of "deliberately left unresolved" case `parseDcFormula`'s own comment (`scraper.mjs:264-276`) calls out for feat-granted ASI abilities.
- **Actual (compendium data):** Empty — matches.
- **Gap / verdict:** Not a meaningful gap; nothing safely automatable here without guessing a value the player is supposed to choose.

### Creature Type
- **Prose:** "You are a Humanoid."
- **Expected (current code):** No detector for a bare creature-type statement exists in `scanSegmentText`. By design, creature type is hardcoded on the **race item**: `assembleRaceItem` (`ddb-scraper.mjs:342-346`) unconditionally sets `system.type.value: "humanoid"` for every imported species (not derived from trait prose or DDB's `creatureTypeId`), so this trait's own text is redundant with — not a source for — the race item's real field.
- **Actual (compendium data):** Empty — matches expectation for the trait item.
- **Gap / verdict:** Not a gap in trait-item handling. As with Size, the actual mechanical value lives on the (missing) race item, so it doesn't exist anywhere in Gnome's current data.

### Speed
- **Prose:** "Your Speed is 30 feet."
- **Expected (current code):** Doesn't match any of `scanSegmentText`'s three speed regexes (`scraper.mjs:712-740`, all requiring "...speed increases by/to N feet" or "you have a...speed of N feet") — "Your Speed is 30 feet" is a bare absolute statement none of them anchor on. Also doesn't match `mergeTraitDerivedMovement`'s `ABSOLUTE_SPEED_GRANT`/`WALKING_SPEED_INCREASES_TO` regexes (`ddb-scraper.mjs:273-274`), which need the same "you have a/an X speed of" or "your base walking speed increases to" wording. Intentional: base walking speed is meant to come from `raceDef.weightSpeeds.normal` (structured DDB data) on the race item, not from parsing this trait's own descriptive sentence.
- **Actual (compendium data):** Empty — matches.
- **Gap / verdict:** Not a gap in the trait item's own handling. Same downstream problem as Size/Creature Type: no race item exists, so the 30 ft base speed this trait describes isn't recorded anywhere for Gnome right now.

### Darkvision
- **Prose:** "You have Darkvision with a range of 60 feet."
- **Expected (current code):** Matches the short-form darkvision regex (`scraper.mjs:752-758`: `darkvision(?:\s+(?:out to|with|to|of|radius of)\s+...)?\s*(\d+)\s*feet`). Empirically confirmed: `scanSegmentText` returns `effectHints: [{ key: "system.attributes.senses.darkvision", mode: 4, value: "60" }]`, which `guessQueueEntries` (`effects-builder.mjs:901-913`) turns into one transfer:true ActiveEffect named "Darkvision" with that change (mode 4 = "upgrade," so it only applies if better than what the actor already has — correct behavior for a passive racial sense).
- **Actual (compendium data):** Empty — a real deviation from what current code would produce (attributable to the stale, pre-issue-011/012/013 import, not a code gap).
- **Gap / verdict:** No gap. This is the one Gnome trait that the current pipeline handles correctly end-to-end.

### Gnomish Cunning
- **Prose:** "You have Advantage on Intelligence, Wisdom, and Charisma saving throws." (Note: this is the 2024 PHB phrasing — no "against magic" qualifier, unlike the 2014 version.)
- **Expected (current code):** Checked against both plausible candidate detectors: (1) the saving-throw detector (`scanSegmentText`, `scraper.mjs:459-469`) requires a single **named** ability immediately before "saving throw(s)" (`/\b(Strength|Dexterity|...)\s+saving throws?\b/i`) to populate `savingThrow` — Gnomish Cunning names three abilities in a comma list before a plural "saving throws," which the singular-ability regex doesn't parse into three separate results (and this detector exists to catch a save *the feature imposes/reduces*, not a blanket save-advantage buff, so it's the wrong shape entirely even if it matched); (2) the resistance/immunity effect-hint block (`scraper.mjs:582-640`) requires "resistance/immunity/vulnerability... to... damage" or "immune to... condition" — Gnomish Cunning says neither. Confirmed via `grep -i "advantage" scripts/scraper.mjs` (and `effects-builder.mjs`/`ddb-scraper.mjs`) returning **zero matches** anywhere in the codebase — there is no "advantage on saving throws" detector of any kind, for any phrasing.
- **Actual (compendium data):** Empty — matches.
- **Gap / verdict:** Confirmed total miss, and confirmed as a real detector gap rather than a by-design omission — dnd5e does expose a real schema shape for save advantage (e.g. per-ability `system.abilities.<key>.bonuses`/advantage flags), but nothing in this pipeline's vocabulary targets it. Not covered by issues 001-019.

### Ability Score Increases
- **Prose:** "When determining your character's ability scores, increase one score by 2 and a different one by 1, or increase three scores by 1. None of these increases can raise a score above 20."
- **Expected (current code):** `guessAbilityScoreImprovement` (`scraper.mjs:881-910`) only matches a sentence starting with `Increase (your|one ability score of your choice|two ability scores of your choice)` (regex at line 884) — this is documented in the function's own header comment as targeting the *feat-level* ASI/Epic-Boon boilerplate, not the species-level phrasing. Empirically confirmed: calling `guessAbilityScoreAdvancement()` directly on this exact HTML returns `null`. `guessProficiencyAdvancement` also returns `{}` (no proficiency/language clause). No `AbilityScoreImprovement` advancement is built.
- **Actual (compendium data):** `advancement: {}` — matches.
- **Gap / verdict:** Confirmed miss, not explained by staleness (current code, run right now, still produces nothing). This exact gap and exact phrasing have already been independently confirmed in the Halfling, Human, and Dwarf species audits — Gnome is now the fourth of nine core 2024 species confirmed to hit it, strongly reinforcing that this is universal boilerplate across all nine core PHB species and not species-specific. Not covered by any of issues 001-019 (issue 009 only wired the already-correct feat-phrasing regex into `buildAutoMechanics`; it never addressed the species-phrasing gap).

## Species-level notes

- **Race item absence (finding #1):** `importDdbRace` (`importer.mjs:929-963`) builds all 8 trait items first (each `await`ed to completion, which is why they persisted), then calls `createItemFromData(assembleRaceItem(...), ...)` for the race item, all inside one outer `try`. Static review of `assembleRaceItem`, `buildSizeAdvancement`, `mergeTraitDerivedMovement`, and `createItemFromData`/`resolveItemUuids` found no species-name branch or "skip if already exists" check that would treat Gnome differently from the 7 non-core species that did get race items — same code path for both. That points to something throwing at runtime specifically for the 9 core species (caught by the outer `catch`, routed to `report.failed`, which isn't part of the data available to this audit). This import also ran on 2026-08-24 ~16:52 UTC against commit `41042a6` (the last commit before that timestamp — `0fbac1e` and everything after landed the next day), well before the Size/movement (issues 014/015) and ASI-wiring (issue 009) work existed, so whatever threw was in an even earlier version of `assembleRaceItem` than what's on disk now. Confirming the exact trigger would require the original `report.failed` message or a fresh console-logged re-import attempt against a core species — outside what static code reading can settle.
- **Folder placement:** All 8 traits sit under `Species/Traits/Gnome` per `raceTraitFolderSegments` (`ddb-scraper.mjs:174-176`), matching the pack layout described in the brief.
- **Uncommitted working-tree code (016/017/019):** already implemented on disk per the Summary note, and relevant to exactly one trait here — Gnomish Lineage's Forest/Rock Gnome sub-options, where issue 019's verb-widening is what lets "Speak with Animals" match at all (pre-019 code only recognized "cast(s/ing)," not "have"), while the newly-surfaced cantrip-overshoot bug and the missing `@prof` uses-formula remain unfixed by either 016, 017, or 019.
- **Most significant findings:** (1) the Ability Score Increases phrasing gap, now confirmed across four species and almost certainly all nine — a single regex/boilerplate fix here would restore ASI advancement pack-wide; (2) the "advantage on saving throws" detector gap, confirmed to have zero code coverage of any kind; (3) the cantrip-name overshoot bug in the spell-name fallback scanner, which is new, Gnome-specific in this audit but structurally likely to recur on any other lineage/subrace trait phrased as "you know the X cantrip(s)" rather than "...X spell."
